# Помощник судьи

Нативное приложение Flutter для судейства соревнований. Сервер FastAPI хранит данные в PostgreSQL, отправляет обновления по WebSocket и формирует PDF. Приложение сохраняет оценки офлайн в SQLite.

## Учебный стенд

Нужны Docker Compose и Flutter 3.44.6. Команды выполняются из корня репозитория.

```sh
export POSTGRES_PASSWORD="$(openssl rand -hex 24)"
docker compose up -d --build
docker compose exec api python -m server.admin organizer org@example.test "Организатор"
```

По запросу введите пароль минимум из восьми символов с буквами и цифрами. Почтовый ящик стенда находится на http://localhost:8025, документация API — на http://localhost:8000/docs. Для Android-эмулятора используйте перенаправление порта. На iOS Simulator доступен адрес хоста по умолчанию.

```sh
adb reverse tcp:8000 tcp:8000
cd mobile
flutter pub get --enforce-lockfile
flutter run --dart-define=API_URL=http://127.0.0.1:8000
```

**Организатор.** Пригласите судей по email, создайте соревнование и укажите адреса бригады и главного судьи. Добавьте участников вручную либо загрузите Excel. Для импорта используйте столбцы «Фамилия», «Имя», «Дата рождения», «Клуб», «Стартовый номер», «Комментарий», «Согласие» в указанном порядке. Дату вводите как дату Excel или ГГГГ-ММ-ДД. Для несовершеннолетнего зафиксируйте согласие представителя. После предпросмотра подтвердите корректные строки. Запуск фиксирует состав бригады, категории и участников.

**Судья.** Откройте из письма ссылку приглашения, задайте пароль и войдите. Заранее откройте нужное соревнование с сетью. Выберите участника, введите технику и артистизм и подтвердите отправку. Без сети оценка остаётся в очереди. При восстановлении связи открытое соревнование автоматически синхронизируется. Для исправления выберите ранее оценённого участника и укажите причину.

**Главный судья.** Разрешайте запрошенные исправления в списке участников. После завершения соревнования организатором сформируйте протокол, проверьте PDF, затем утвердите и отправьте по email. Утверждение фиксирует версию, имя главного судьи и время. [Учебный образец протокола](docs/protocol-sample.pdf)

Возраст определяется на дату соревнования. Границы по умолчанию — 13, 18 и 40 лет. До трёх назначенных судей считаем обычное среднее, от трёх удаляем одну минимальную и одну максимальную оценку по каждому компоненту. После получения всех оценок считаем итог с весами 0,6 и 0,4. Для мест сравниваем округлённые до сотых итог и технику. При полном равенстве присваиваем общее место.

## GitHub Actions и защита

PR запускает тесты FastAPI с PostgreSQL, Flutter widget-тесты, тесты реальной SQLite, статический анализ, проверку матрицы требований и порогов покрытия. Каждый push в main и ручной запуск в **Actions → Judge Helper acceptance → Run workflow** дополнительно запускают Android API 28 и 35, симуляторы iPhone и iPad, нагрузку 50 пользователей на 500 участников, восстановление PostgreSQL и self-healing через OpenRouter. Результаты и сборки доступны на странице запуска. [Workflow](.github/workflows/acceptance.yml) · [Соответствие тестов Jira](ci/matrix.py)

Для живого self-healing задайте в настройках Actions секрет `OPENROUTER_API_KEY` и переменную `OPENROUTER_MODEL` с идентификатором модели в OpenRouter. Appium нажимает кнопку исходным локатором, затем демонстрирует восстановление устаревшего локатора. Модель получает только список разрешённых кнопок диалога. Проверка через API сверяет автора, участника, оба балла и версию. Третий пример использует отдельный тестовый сервер, который намеренно сохраняет ошибочный балл. Ожидаемый исход этого примера — обнаруженный дефект. Отчёт сохраняется в `self-healing.json`.

Автотесты используют синтетические данные. Версия ОС каждого симулятора указана в артефактах. Фактическая доставка системных push на физический телефон и работа на устройстве с iOS 15 требуют отдельного прогона. Минимальные версии сборки — Android 9 и iOS 15.

## Внешние сервисы и эксплуатация

Для Яндекс ID зарегистрируйте приложение, задайте публичный HTTPS-адрес `PUBLIC_URL`, redirect URI `PUBLIC_URL/yandex/callback`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` и право на email. Вход связывается с активной приглашённой учётной записью. Почтовый worker поддерживает `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `SMTP_TLS=1`, `SMTP_USER` и `SMTP_PASSWORD`. Для реальной почты передайте их сервису delivery через override Compose.

Для FCM зарегистрируйте платформы в Firebase. Передайте Flutter через `--dart-define` параметры `FCM_PROJECT`, `FCM_API_KEY`, `FCM_APP_ID` и `FCM_SENDER`. Для iOS настройте подписанный Push Notifications entitlement и ключ APNs в Firebase. Смонтируйте сервисные учётные данные в контейнер delivery и задайте его `GOOGLE_APPLICATION_CREDENTIALS`. Для каждого события пользователь может отдельно отключить доставку.

Для стенда с публичным доменом задайте `SITE_HOST`, `PUBLIC_URL` и включите профиль `docker compose --profile tls up -d`. Сервис backup ежедневно пишет архив PostgreSQL в `backups/`. Для восстановления создайте отдельную пустую БД и выполните `pg_restore --exit-on-error --dbname=<новая БД> <архив>`. В CI восстанавливаются и сравниваются все таблицы. Путь `/health` проверяет доступ к БД. Для удаления идентифицирующих полей участника до утверждения предусмотрена команда `python -m server.admin anonymize EVENT_ID NUMBER`. Размещение в России, порядок получения согласия и сроки хранения данных утверждённых протоколов определяет оператор перед работой с реальными участниками.
